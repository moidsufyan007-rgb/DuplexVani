🔴 The Problem

India's 7,000+ APMC mandis and 12 million kirana stores run entirely on voice — not apps, not forms. Existing voice bots are half-duplex: they stop listening when they speak. The moment a trader tries to interrupt, correct a price, or change an order mid-sentence, the bot either mishears, ignores, or restarts. For real Bharat commerce — noisy mandis, 8kHz phone lines, Hinglish dialects — this fails completely.

✅ The Solution
Sub-16ms Barge-In Preemption

Web Audio API energy VAD detects interruption in a single 16ms frame. asyncio.Task.cancel() stops the AI mid-sentence instantly — no lag, no overlap, no restart.

APMC Mandi Trade State Machine

7-state deterministic engine: IDLE → COMMODITY → QUANTITY → PRICE → CONFIRMED → EXECUTED. LLM extracts intent; state machine enforces correctness. AI cannot corrupt a trade.

Gnani AI Voice Stack

Gnani Prisma v3.0 STT + Timbre v3.0 TTS — optimized for 8kHz GSM telephony and Hindi / Hinglish / Telugu code-switching out of the box. No language selection needed.

Zero Literacy Barrier

Phonetic normalization handles "do sau kilo sarso", "teen hazaar rate do". Farmers and kirana owners book trades, check rates, and manage credit entirely by voice.

🏗️ Architecture
[User Voice] → Gnani Prisma STT → Gemini Flash LLM (intent only) → Trade State Machine
                                                                                        ↓
[User Hears] ← Gnani Timbre TTS ← Response Generator ← State Transition Output
                      ↑
                   Sub-16ms VAD Barge-In interrupts this pipeline at ANY point
